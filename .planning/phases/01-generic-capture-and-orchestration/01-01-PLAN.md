# Plan 01-01: Contracts, Generic Capture, and Orchestration

## Objective

Implement the typed generic page contract and asynchronous orchestration that combines generic capture with the existing first-match specialized parser.

## Tasks

1. Extend the contracts with JSON-safe generic page, cookie, metadata, timing, specialized-capture, and combined-result types while retaining compatible Asana/parser types where practical.
2. Add a generic capture boundary that reads only the injected/current browser context, maps URL/document/meta/link/viewport/screen/navigation data, and never returns DOM objects.
3. Implement Cookie Store preference, stable cookie mapping, `document.cookie` fallback, stable unavailable/failure/fallback diagnostics, empty-cookie preservation, and no-value logging.
4. Change parser output to allow a value or promise, make `captureCurrentTab()` await generic and specialized work, preserve first-match registry selection, and derive the specified complete/partial/failed statuses.
5. Preserve report-window error handling for rejected capture work and keep specialized parser exceptions attached to the combined result as `SPECIALIZED_PARSER_FAILED`.

## Must Haves

- No specialized match is a normal generic result without `NO_PARSER_MATCHED`.
- Generic data survives specialized warning, target-not-visible, and exception paths.
- Asana remains available through the existing explicit registry.
- Every returned value is serializable plain data.

## Verification

Run the focused capture/orchestration tests, the full Node test suite, and `npm run typecheck`. Inspect the resulting public types for erasable syntax and explicit `.ts` imports.

## Dependencies

None beyond the existing source and test tooling.
