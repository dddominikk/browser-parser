# Plan 03-02: Explicit Secret-Gist Deployment

## Objective

Add a safe, testable command that rebuilds and updates exactly the configured bundle file in an existing secret gist.

## Tasks

1. Add `deploy:mjs-bundle-gist` orchestration that runs the bundle build first and validates bundle/config prerequisites.
2. Encapsulate `gh` authentication, gist lookup, PATCH payload, and remote verification behind an injectable command runner; avoid shell-quoting bundle contents.
3. Handle replacement and creation of the configured filename, preserve unrelated gist files, reject inaccessible/missing gists, and verify remote bytes/checksum.
4. Add unit tests for missing bundle/config, inaccessible gist, replacement, absent file creation, preservation, remote verification failure, and secret-safe output.
5. Define the manual authenticated smoke-test procedure, including exact non-secret evidence to record and the privacy gate required before using the real gist.

## Must Haves

- No automatic gist creation or ordinary-CI deployment.
- Success output does not print the full raw URL or bundle contents.

## Verification

Run injected-runner tests. Defer the real authenticated smoke test until Phase 4's privacy-transition checks approve it.
