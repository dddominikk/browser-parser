# Plan 05-01: Embedded Page Metadata Explorer

## Objective

Give the existing report tab an optional miniature browser window for navigating to an HTTP(S) address and displaying basic metadata immediately below a successfully loaded, same-origin iframe document, with clear inline errors for invalid input or inaccessible pages.

## Tasks

1. Add typed iframe metadata contracts plus pure helpers for scheme normalization and same-origin document inspection.
2. Build the closed-by-default `<details>` explorer with a compact toolbar, inert URL input, iframe, metadata result area, loading state, and error state; keep it independent from the main capture result.
3. Insert the explorer into the report renderer and keep all untrusted values in `textContent`/DOM properties, with static styling only.
4. Add tests for address normalization/rejection, metadata extraction, iframe accessibility failures, rendered structure, interaction callbacks, and hostile metadata text.
5. Update README and planning verification evidence, then run source import, tests, typecheck, and deterministic bundle validation.

## Must Haves

- No new runtime dependency or cross-origin bypass.
- `https://` is inferred only when the user omits a URL scheme.
- HTTP(S)-only validation rejects executable and local-resource schemes.
- Successful loads render URL, title, description, canonical, and Open Graph metadata below the iframe.
- Invalid, inaccessible, and load-error paths are visible inline and do not break the main capture report.
- Dynamic values cannot become executable markup.

## Verification

Run `npm run validate`, `npm run build:mjs-bundle`, and the focused iframe/report tests. Inspect the diff for generated-output or secret changes. Manual Edge smoke remains a follow-up for real cross-origin/browser-policy behavior.

## Dependencies

Existing report surface, browser DOM APIs, Node built-in test runner, and TypeScript DOM typings.
